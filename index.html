Qué vas a conseguir

Publicar sin programar

Subir una carpeta con un index.html y obtener una dirección pública con HTTPS en minutos.

Actualizar con seguridad

Conectar GitHub para que cada cambio se publique solo, con una vista previa antes de llegar a producción.

No romper nada

Entender los entornos y usar Instant Rollback para recuperar una versión buena.

Ir más allá

Dominio propio, variables de entorno, una API sencilla y control de costes.

Qué necesitas para empezar

  • Un ordenador con navegador actualizado (Windows, macOS o Linux).
  • Un correo electrónico o una cuenta de GitHub, GitLab o Bitbucket.
  • Nada más para la primera publicación. Node.js y la terminal solo hacen falta más adelante y son opcionales.

Cómo usar este tutorial

  • Ocho pestañas con contenido independiente. La pestaña activa se recuerda en la dirección (#conceptos, #procedimiento…).
  • Progreso guardado: el tema, el tamaño de letra y las listas de comprobación se conservan en tu navegador.
  • Buscador: escribe dos o más letras y salta al punto exacto de cualquier pestaña.
  • Botones COPIAR en los bloques de código e instrucciones: copian el contenido íntegro, sin añadir nada.
  • Impresión o PDF: el botón 🖨 prepara todas las secciones, abre los desplegables y monta las ilustraciones antes de imprimir.
  • Móvil: el diseño es de una sola columna; las tablas anchas se desplazan en horizontal.

Cómo se marca la información

La guía de origen distingue lo documentado de lo supuesto. Este tutorial conserva ese sistema para que sepas qué puedes dar por comprobado y qué debes verificar:

EtiquetaSignificado
DOCAfirmación tomada de una página oficial de Vercel leída completa en la fecha de consulta de la fuente (16/10/2026).
DOC-PARCIALAfirmación vista en un fragmento de una página oficial, sin haber leído la página entera. Compruébala antes de depender de ella.

Honestidad sobre las pruebas. La guía de origen declara que no ejecutó comandos ni desplegó proyectos: todo su contenido práctico es NO PROBADO. Este tutorial hereda esa declaración. Además, el archivo que estás leyendo se ha construido y revisado de forma estática: no se ha ejecutado en un navegador real desde el entorno de generación. Las funciones interactivas están implementadas, pero su prueba final corresponde a quien abre el archivo.

Conceptos: el vocabulario mínimo para no perderte

No necesitas programar para publicar una web, pero sí entender una docena de palabras. Cada concepto se explica antes de usarlo.

1. ¿Qué es Vercel?

Vercel es una plataforma en Internet donde publicas webs y aplicaciones para que cualquiera pueda abrirlas desde su navegador. Todo lo que publicas vive en un proyecto: puede ser una web, una API, tareas programadas, contenedores o cargas de trabajo de inteligencia artificial DOC.

Analogía: tu web es un libro. Escribirlo en tu ordenador es desarrollar. Vercel es la librería con escaparate donde el libro queda expuesto, ordenado, protegido y accesible las 24 horas.

2. Desplegar, alojar y publicar

  • Desplegar (deploy): copiar tu proyecto a los ordenadores de Vercel, prepararlo (compilarlo si hace falta) y hacerlo accesible mediante una dirección.
  • Alojamiento u hosting: el servicio de tener esos archivos en ordenadores conectados a Internet permanentemente.
  • Publicar: dejar una versión visible para el público en la dirección definitiva.

3. Los tres entornos

FaseDónde ocurreQuién lo veNombre en Vercel
DesarrollarTu ordenadorSolo túLocal / Development
ProbarUna copia publicada aparteTú y quien invitesPreview (vista previa)
PublicarLa dirección definitivaTodo el mundoProduction (producción)

Vercel define exactamente esos tres entornos por defecto DOC. Regla especial: el primer despliegue de un proyecto nuevo es siempre de producción, aunque lo hagas desde otra rama DOC.

4. Proyecto y despliegue

Un proyecto agrupa despliegues, dominios, variables de entorno y ajustes. Un despliegue es una versión concreta e inmutable de ese proyecto: no se modifica después; publicar consiste en apuntar el dominio de producción a un despliegue existente.

5. Git, GitHub y el flujo de trabajo

  • Repositorio: carpeta de proyecto con historial de todos sus cambios.
  • Git: programa que registra ese historial en tu ordenador.
  • GitHub: servicio web que guarda repositorios en la nube y permite colaborar.
  • Commit: una «foto» con mensaje de los cambios en un momento.
  • Rama (branch): línea paralela de trabajo. main suele ser la de producción.
  • Pull request (PR): petición de fusionar una rama en otra, con revisión.
  • Merge: fusionar los cambios de una rama en otra.

Cuando conectas un repositorio, cada subida a la rama de producción genera un despliegue de producción y cada subida a otra rama genera una vista previa DOC.

6. La web por dentro: HTML, CSS y JavaScript

LenguajePara qué sirveAnalogía
HTMLEstructura y contenido (títulos, párrafos, enlaces)Muros y habitaciones de una casa
CSSAspecto (colores, tamaños, tipografías)Pintura y decoración
JavaScriptComportamiento (botones que hacen cosas)Electricidad y mecanismos

Ejemplo mínimo de HTML:

<!doctype html>
<html lang="es">
  <head><meta charset="utf-8"><title>Hola</title></head>
  <body><h1>Hola, mundo</h1></body>
</html>

Cada parte entre < y > es una etiqueta. <h1> es un título principal.

7. Framework

Un framework es un conjunto de herramientas y reglas que facilita crear webs grandes: Next.js, Astro, SvelteKit, Nuxt, Vite… Vercel detecta automáticamente el framework y configura la compilación DOC. Si no lo detecta, puedes elegir el preset a mano.

8. Terminal, Node.js y npm

  • Terminal: ventana donde escribes órdenes de texto (comandos) en lugar de hacer clic.
  • Node.js: permite ejecutar JavaScript fuera del navegador; muchas herramientas web lo necesitan. La documentación de Vercel indica Node.js 18 o superior para la CLI DOC.
  • npm: viene con Node.js y sirve para instalar paquetes. npm i -g vercel instala la CLI de Vercel de forma global DOC.
SistemaCómo abrir la terminal
Windows 11Tecla Windows, escribe PowerShell o Terminal y pulsa Intro
macOSCmd + Espacio, escribe Terminal, Intro
LinuxCtrl + Alt + T en muchas distribuciones

9. Dominio, DNS y HTTPS

  • Dominio: nombre legible de tu web (ejemplo.com).
  • Dominio apex o raíz: el nombre sin prefijo (ejemplo.com).
  • Subdominio: prefijo delante (www.ejemplo.com, blog.ejemplo.com).
  • DNS: «agenda telefónica» de Internet que traduce nombres de dominio a direcciones numéricas.
  • HTTPS: conexión cifrada (candado del navegador). Vercel emite el certificado SSL automáticamente tras verificar el dominio DOC.
Registro DNSQué hace
AApunta un nombre a una dirección IPv4
AAAAApunta un nombre a una dirección IPv6
CNAMEHace que un nombre sea alias de otro nombre
TXTGuarda texto: verificaciones de propiedad, políticas de correo
MXIndica qué servidores reciben el correo del dominio

Nunca borres registros DNS «para limpiar». Los MX y TXT mantienen el correo y la verificación de otros servicios. Antes de cambiar algo, haz una captura o exporta la zona DNS.

10. Variables de entorno

Una variable de entorno es un par NOMBRE=valor disponible para tu aplicación durante el build o la ejecución. Sirve para claves de API, direcciones de bases de datos y ajustes que cambian entre pruebas y producción. Vercel las cifra en reposo y los cambios solo se aplican a despliegues nuevos DOC.

TipoSe puede volver a leerCuándo usarlo
ConfigSí, el valor se ve en el panelAjustes no secretos (API_URL, flags)
SecretNo (solo escritura)Claves, tokens, contraseñas

Un Secret no puede volver a leerse ni convertirse en Config: si necesitas cambiarlo, lo sobrescribes DOC.

11. Funciones de servidor y APIs

  • Petición HTTP: mensaje que envía el navegador a un servidor («dame esta dirección» o «recibe estos datos»).
  • Respuesta HTTP: lo que devuelve el servidor, con un código de estado: 200 correcto, 404 no existe, 500 error del servidor.
  • API: dirección que devuelve datos (normalmente JSON) en lugar de una página.
  • Función de servidor: programa que se ejecuta bajo demanda cuando alguien visita su ruta. Vercel las llama Vercel Functions DOC.

Regla de oro: las claves secretas solo deben usarse en el servidor. Todo lo que llega al navegador es público.

Procedimiento: de cero a una web publicada

Hay tres caminos para publicar. Empieza por el Camino A (el más sencillo). Después conecta GitHub para actualizar sin repetir pasos.

Paso 0. Crea tu cuenta de Vercel

Objetivo: tener una cuenta activa y ver el panel.

Qué necesitas: un correo o una cuenta de GitHub, GitLab o Bitbucket.

  1. Abre https://vercel.com/signup en tu navegador. Deberías ver una pantalla de registro con opciones de acceso.
  2. Elige un método de acceso (por ejemplo, continuar con GitHub si ya tienes cuenta; si no, correo electrónico). Te pedirá confirmar con un código o autorizar en GitHub.
  3. Si el asistente pregunta por el tipo de uso, elige personal/hobby si son proyectos propios y no comerciales. El plan Hobby es solo para uso personal no comercial DOC.
  4. Comprueba que ves el panel: una página con tus proyectos (vacía al principio) y un botón para crear uno.

Por qué funciona: al registrarte, Vercel crea tu equipo personal y lo asocia a tu identidad.

Errores frecuentes:

ErrorSolución
No llega el correo de confirmaciónRevisa spam, espera unos minutos y prueba otro método de acceso.
Registro con GitHub y quiero otra cuenta de GitHubCierra la sesión de GitHub y reinicia el registro DOC.
Entro y no veo mis proyectosMira el selector de equipo (arriba a la izquierda): puede que estés en otro equipo.

Comprobación: cierra sesión, vuelve a entrar y ves el panel.

Paso 1. Prepara tu primer archivo index.html

Objetivo: tener una página que funcione en tu ordenador antes de publicarla.

  1. Crea en tu escritorio una carpeta llamada mi-primera-web.
  2. Dentro, crea un archivo de texto y llámalo exactamente index.html.
    En Windows 11: clic derecho → Nuevo → Documento de texto → renombra. Activa Ver → Mostrar → Extensiones de nombre de archivo; si se queda como index.html.txt, no funcionará.
  3. Abre el archivo con el Bloc de notas, pega el código siguiente y guarda con Archivo → Guardar (UTF-8 si te lo pregunta).
  4. Haz doble clic en el archivo. Deberías ver «¡Hola desde Vercel!» en el navegador.
<!doctype html>
<html lang="es">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Mi primera web en Vercel</title>
  <style>
    body { font-family: Arial, sans-serif; max-width: 40rem; margin: 3rem auto; padding: 0 1rem; line-height: 1.6; }
    h1 { color: #1a1a1a; }
  </style>
</head>
<body>
  <h1>¡Hola desde Vercel!</h1>
  <p>Esta es mi primera web publicada en Internet.</p>
</body>
</html>

Por qué funciona: HTML es el lenguaje que los navegadores entienden; abrirlo localmente comprueba que está bien antes de publicar.

Paso 2 (Camino A). Publica con Vercel Drop

Objetivo: publicar la carpeta sin Git ni terminal.

Conceptos previos: despliegue, producción.

Según la documentación, Vercel Drop permite desplegar un archivo, carpeta o .zip arrastrándolo al navegador, sin Git, CLI ni preparación local DOC-PARCIAL.

  1. Abre https://vercel.com/drop con la sesión iniciada. Deberías ver la página de Drop.
  2. Arrastra la carpeta mi-primera-web (o un .zip que la contenga) a la zona indicada, o elige file/folder. La página reconoce los archivos.
  3. Elige tu equipo y escribe un nombre de proyecto, por ejemplo mi-primera-web. Usa minúsculas, números y guiones.
  4. Pulsa Deploy. Verás una pantalla de progreso y, al terminar, un enlace a tu web.
  5. Abre el enlace. Debe mostrar «¡Hola desde Vercel!».

Por qué funciona: Vercel recibe los archivos, detecta que es una web estática y la publica en su red. Como es el primer despliegue de un proyecto nuevo, se crea como producción DOC.

Errores frecuentes:

ErrorCausa probableSolución
La página dice 404No hay index.html en la raíz de lo arrastrado, o está dentro de otra subcarpetaComprueba que index.html está directamente dentro de la carpeta arrastrada
El archivo se llama index.html.txtExtensiones ocultas en WindowsMuestra extensiones y renombra
No encuentro el botón DeployLa interfaz cambióBusca el botón principal de confirmación en la página de Drop
Nombre de proyecto rechazadoCaracteres no permitidosUsa solo minúsculas, números y guiones

Limitación: cada drop crea un proyecto nuevo; para actualizar a menudo conviene conectar Git después DOC-PARCIAL.

Paso 3 (Camino B, recomendado). Conecta GitHub

Objetivo: publicar un proyecto que vive en GitHub, con despliegue automático en cada cambio.

Qué necesitas: cuenta de GitHub y de Vercel; un repositorio con tu index.html.

A. Crear el repositorio

  1. En https://github.com/new escribe un nombre, por ejemplo mi-primera-web.
  2. Marca Public o Private (ambas funcionan) y pulsa Create repository.
  3. En la página del repositorio vacío, pulsa uploading an existing file, arrastra tu index.html y pulsa Commit changes. El archivo queda listado.

B. Importar en Vercel

  1. Abre https://vercel.com/new DOC.
  2. Conecta tu cuenta de GitHub si no lo has hecho. Cuando GitHub lo pida, autoriza la aplicación de Vercel solo para los repositorios que vas a publicar.
  3. Localiza mi-primera-web y pulsa Import. Verás un formulario con el Framework Preset; para HTML puro suele aparecer «Other».
  4. Revisa la configuración sin cambiar nada: Root Directory vacío o ./; Build Command y Output Directory en blanco para un sitio estático.
  5. Pulsa Deploy DOC. Verás registros de construcción y, al terminar, la dirección .vercel.app.
  6. Abre la dirección y comprueba la página.

Por qué funciona: al importar, Vercel instala una aplicación en GitHub que le avisa de cada subida. Cada subida a la rama de producción crea un despliegue de producción; cada subida a otra rama crea una vista previa DOC.

Permisos importantes: si importas un repositorio personal debes ser su Owner; un simple colaborador no puede. Si pertenece a una organización de GitHub, debes ser Owner de la organización o Member con acceso al repositorio; un Outside Collaborator no puede importarlo DOC. Además, un equipo Hobby no puede conectarse a repositorios de organizaciones Git DOC.

Errores frecuentes:

ErrorSolución
«Unable to find your GitHub repository» o no apareceRevisa permisos y que la app de Vercel tenga acceso a ese repositorio DOC.
Hobby con repositorio de una organizaciónNo permitido; usa un repositorio personal o cambia de plan DOC.
La web sale en blanco o 404Comprueba que index.html está en la raíz y que el repositorio tiene contenido.
Build fallaMira el registro de build (pestaña ERRORES).

Paso 4. Actualiza tu web desde GitHub

Objetivo: cambiar un texto y verlo publicado sin tocar Vercel.

  1. Abre el repositorio en GitHub y haz clic en index.html.
  2. Pulsa el icono del lápiz (editar).
  3. Cambia el texto.
  4. Pulsa Commit changes…, escribe un mensaje descriptivo («Cambio el título») y confirma.
  5. En Vercel, abre Deployments: aparece un despliegue nuevo en construcción y luego Ready.

Por qué funciona: Vercel despliega cada push por defecto, incluidos los hechos a ramas y los pull request DOC.

Cuidado: si commiteas directamente en main, el cambio va directo a producción. Para probar antes, usa una rama (paso siguiente).

Paso 5. Prueba sin publicar: ramas y vista previa

Objetivo: probar un cambio en una dirección de vista previa antes de publicarlo.

  1. En GitHub, abre el desplegable de ramas y escribe cambio-titulo; pulsa Create branch.
  2. Edita un archivo en esa rama y confirma el cambio en la rama, no en main.
  3. En Vercel → Deployments, localiza el despliegue de la rama. Su entorno es Preview. Ábrelo: la producción sigue igual.
  4. En GitHub pulsa Compare & pull request → Create pull request. El bot de Vercel comenta con el enlace de vista previa DOC.
  5. Si todo está bien, pulsa Merge pull request → Confirm. La fusión en main genera el despliegue de producción.

Por qué funciona: Vercel crea un despliegue por rama y comenta en los PR; la rama de producción por defecto es main y se puede cambiar en los ajustes del proyecto DOC.

Paso 6. Vuelve atrás sin pánico: Instant Rollback

Objetivo: recuperar rápido una versión buena si producción se rompe.

  1. Proyecto → Deployments (o la tarjeta de producción del proyecto).
  2. Localiza el despliegue anterior bueno, abre su menú y elige Instant Rollback DOC-PARCIAL.
  3. Confirma. La dirección de producción muestra la versión antigua casi al instante: Vercel reasigna dominios, no recompila.

Muy importante: tras un rollback, Vercel desactiva la asignación automática de dominios de producción. Para restaurar el comportamiento normal debes promover otro despliegue (vercel promote [id o url]). Si no lo haces, los nuevos push no se publicarán automáticamente en producción DOC-PARCIAL.

Por CLI: vercel rollback (al anterior) o vercel rollback <url> DOC-PARCIAL.

Limitación: si borras un despliegue, ya no podrás hacer rollback a él DOC.

Siguiente paso: corrige el error en el código, súbelo y promueve el nuevo despliegue.

Paso 7. Tu dominio propio

Objetivo: que tu web responda en www.ejemplo.com con HTTPS, sin romper el correo.

Qué necesitas: un dominio comprado (en Vercel o en otro registrador) y acceso a su panel DNS.

A. Añadir el dominio en Vercel

  1. Proyecto → Settings → Domains DOC.
  2. Escribe tu dominio y pulsa Add.
  3. Elige qué nombre será el principal: www o el apex (ejemplo.com); el otro redirigirá.
  4. Verás el dominio en estado Invalid Configuration hasta que configures el DNS, junto a una tabla de registros recomendados.

B. Elegir método DNS

Vercel documenta dos vías: A/CNAME (configuras registros en tu registrador) o nameservers de Vercel (delegas todo el DNS en Vercel) DOC.

  • Si no tienes correo ni otros servicios en ese dominio, delegar es lo más sencillo.
  • Si ya usas correo u otros servicios, usa A/CNAME para no tocar el resto de registros.

C. Método A/CNAME

  1. Abre el panel DNS de tu registrador (suele llamarse DNS, Zona DNS o Advanced DNS).
  2. Crea los registros que Vercel te muestra para tu proyecto. La documentación cita como valores generales 76.76.21.21 (registro A para el apex) y cname.vercel-dns-0.com (CNAME para www), pero aconseja usar los valores específicos de tu proyecto, visibles en Settings → Domains al pulsar «Learn more» o con vercel domains inspect / vercel domains verify DOC.
  3. Si ya existe un registro A/CNAME con el mismo nombre, edítalo en lugar de duplicarlo.
  4. Guarda y espera la propagación.

D. Método nameservers de Vercel

Cambia en el registrador los servidores de nombres a ns1.vercel-dns.com y ns2.vercel-dns.com DOC-PARCIAL (confírmalos en tu panel). Atención: al delegar, Vercel pasa a gestionar toda la zona DNS; debes recrear en Vercel los registros que ya tenías (MX, TXT y cualquier otro) o perderás el correo.

E. Verificar

  1. Vuelve a Settings → Domains: el estado debe pasar a Valid Configuration cuando el DNS se propague.
  2. Por CLI: vercel domains verify ejemplo.com --project mi-primera-web DOC.
  3. Abre https://ejemplo.com y comprueba el candado. Vercel emite el certificado automáticamente tras verificar el DNS DOC.

Errores frecuentes:

SíntomaCausaSolución
Invalid Configuration persistenteEl DNS no apunta a Vercel o aún no se propagóRevisa los valores exactos; espera; usa vercel domains verify
El dominio ya está en otra cuentaAsociado a otro proyecto o equipoElimínalo allí o verifica la propiedad con el TXT que indique Vercel
Error de certificado HTTPSDNS sin propagar o un registro CAA restringe la emisiónEspera; si usas CAA, permite letsencrypt.org DOC-PARCIAL
Dejó de funcionar el correoSe borraron o perdieron los MX al delegarRecrea los MX en el panel DNS

Paso 9. Tu primera API

Objetivo: crear una función de servidor que devuelva JSON.

En proyectos que no usan un framework con su propio sistema de rutas, crea una carpeta api en la raíz y coloca archivos de función dentro; cada archivo se convierte en una ruta /api/<nombre> DOC-PARCIAL.

Crea api/hola.js con este contenido NO PROBADO:

// Una función de servidor muy simple.
// "req" = petición recibida; "res" = respuesta que enviaremos.
module.exports = (req, res) => {
  res.status(200).json({ mensaje: "Hola desde una función de Vercel" });
};
  • module.exports = (req, res) => { ... }: entrega a Vercel una función que recibe la petición y la respuesta.
  • res.status(200): fija el código de estado a «correcto».
  • .json({...}): envía un objeto como JSON.

Tras desplegar, visita https://TU-PROYECTO.vercel.app/api/hola. Debe mostrar {"mensaje":"Hola desde una función de Vercel"}.

Probar en local (opcional): en la carpeta del proyecto, ejecuta vercel dev (necesita CLI y vercel link) DOC-PARCIAL y abre http://localhost:3000/api/hola. El puerto puede variar; mira la salida del comando.

Límites relevantes DOC: el build tiene un máximo de 45 minutos; el tamaño total de variables de entorno por despliegue es de 64 KB. Memoria, duración máxima y tamaño de las funciones varían por plan: consulta la página oficial de límites.

Errores: 404 → la carpeta api no está en la raíz o el archivo se llama distinto; 500 → error en el código, mira los registros; 504 → la función tardó más del máximo del plan.

api/saludo.js

// API de saludo: recibe ?nombre=... y devuelve un saludo en JSON.
// MENSAJE_BASE es una variable de entorno (tipo Config) definida en Vercel.
module.exports = (req, res) => {
  // 1) Leer el nombre de la URL. req.query contiene los parámetros (?nombre=Ana).
  const nombreCrudo = (req.query && req.query.nombre) || "visitante";

  // 2) Limpiar y limitar el texto para evitar entradas absurdas.
  const nombre = String(nombreCrudo).trim().slice(0, 40) || "visitante";

  // 3) Leer la variable de entorno. Si no existe, usamos un valor por defecto
  //    y avisamos en la respuesta (así se detecta si olvidaste configurarla).
  const base = process.env.MENSAJE_BASE;
  const configurada = Boolean(base);
  const mensaje = (base || "Hola") + ", " + nombre + "!";

  // 4) Responder con JSON y un código 200 (correcto).
  res.status(200).json({
    mensaje: mensaje,
    variableMensajeBaseConfigurada: configurada
  });
};

      aviso.textContent = "";
      try {
        const nombre = encodeURIComponent(campo.value.trim());
        const respuesta = await fetch("/api/saludo?nombre=" + nombre);

Método: lee el mensaje exacto; comprueba lo más probable primero; cambia una cosa cada vez; verifica; si no basta, aplica la alternativa.

Error de compilación (build failed)

Síntoma: el despliegue termina en Error y el registro acaba con «Build failed».

Causas posibles: error en el código; dependencia ausente; comando de build erróneo; variable de entorno ausente; versión de Node distinta.

Comprobaciones: abre el registro de build y busca la primera línea de error; ejecuta el build en local (npm run build).

Solución: corrige lo que indica esa línea y sube el cambio. Como alternativa, haz Redeploy sin caché de build DOC.

Página en blanco o 404

Causas: falta index.html en la raíz; framework mal detectado; Output Directory incorrecto; el build no genera la carpeta esperada.

Comprobaciones: mira Framework Preset y Output Directory; ejecuta el build en local y observa qué carpeta aparece.

Solución: elige el preset correcto (o «Other» para HTML puro); ajusta la carpeta de salida; redeploy.

Variables de entorno: undefined o error de conexión

Causa confirmada: los cambios solo afectan a despliegues nuevos; la variable puede estar en otro entorno DOC.

Comprobaciones: vercel env ls; panel → Environment Variables; nombre exacto, con mayúsculas.

Solución: añade o corrige la variable y redeploy. Si es del navegador, revisa el prefijo público de tu framework.

El dominio no funciona
  1. ¿Estado en Vercel Valid Configuration? Si no, revisa los registros.
  2. ¿Has esperado la propagación? Prueba desde otra red o el móvil con datos.
  3. ¿Hay un registro duplicado o contradictorio?
  4. ¿El dominio está asociado a este proyecto y al despliegue de producción?
  5. ¿Hay protección de despliegue que pida iniciar sesión?
  6. Ejecuta vercel domains verify ejemplo.com --project NOMBRE.

Alternativa: usa temporalmente la dirección .vercel.app para confirmar que el problema es solo del dominio.

Error HTTPS

Causas: Vercel emite el certificado tras verificar el DNS DOC; el DNS puede no haberse propagado; un registro CAA puede impedir la emisión; puede quedar un certificado antiguo del proveedor.

Comprobaciones: estado del dominio; vercel certs ls; registros CAA.

Solución: corrige el DNS, espera y, si usas CAA, permite al emisor. Como alternativa, elimina y vuelve a añadir el dominio en el proyecto.

El repositorio no aparece al importar

Causas confirmadas DOC: no eres Owner del repositorio personal; eres Outside Collaborator de una organización; equipo Hobby con repositorio de organización; la app de Vercel no tiene acceso a ese repositorio.

Solución: concede acceso a la app de Vercel para ese repositorio; pide ser Member u Owner; usa un repositorio personal. Si cambiaste de cuenta de GitHub, cierra sesión en GitHub y reinicia el proceso.

Despliegue bloqueado o en espera

Causas: un PR desde un fork sin autorizar; el autor del commit no es miembro del equipo; producción en espera («staged»).

Solución: autoriza el despliegue (propietario o miembro) o promueve manualmente. Como alternativa, añade al colaborador al equipo.

Tras un rollback, los cambios nuevos no llegan a producción

Causa: el rollback desactiva la asignación automática de dominios de producción DOC-PARCIAL.

Solución: promueve un despliegue nuevo (vercel promote <url>) para restaurar el comportamiento normal.

Causas posibles: variables distintas; versión de Node distinta; un archivo ignorado por .gitignore que se necesita; mayúsculas y minúsculas distintas en nombres de archivo (Linux distingue, Windows no); rutas absolutas del PC.

Ves una versión antigua (caché)

Causas: caché del navegador; cabeceras Cache-Control; redirecciones permanentes guardadas.

Comprobaciones: ventana de incógnito; actualización forzada (Ctrl + F5); revisa cabeceras en vercel.json.

Solución: acorta la caché de las rutas que cambian; usa nombres nuevos para recursos con caché larga. Como alternativa, Redeploy sin caché de build DOC.

Consumo o factura inesperados

Causas posibles: bucle de llamadas a tu API; bots; imágenes enormes; builds frecuentes; app con IA sin límites.

Comprobaciones: panel de Usage por producto y proyecto.

Solución: limita, cachea, optimiza y pausa lo que no uses; configura topes o alertas de gasto donde existan.

Errores de permisos

Causa: tu rol en el equipo no permite esa acción DOC-PARCIAL.

Solución: pide a un Owner que haga el cambio o que ajuste tu rol. Como alternativa, usa un grupo de acceso con permisos específicos.

Resumen: lo esencial en diez reglas

  1. El primer despliegue de un proyecto nuevo es siempre producción.
  2. Usa ramas y vistas previas para probar antes de publicar.
  3. Los cambios en variables de entorno solo se aplican a despliegues nuevos: haz redeploy.
  4. Tras un rollback, promueve un despliegue nuevo para reactivar la publicación automática.
  5. Nunca pongas claves en el código ni en el navegador: usa variables Secret en el servidor.
  6. Nunca borres registros DNS MX o TXT sin saber qué hacen.
  7. El plan Hobby es solo para uso personal no comercial.
  8. Los precios y límites cambian: compruébalos en las páginas oficiales antes de contratar.
  9. Lee el registro de build de abajo arriba y cambia una sola cosa cada vez.
  10. Documenta tu procedimiento de publicación y de incidentes: otra persona debería poder seguirlo.

Preguntas frecuentes

¿Necesito saber programar para usar Vercel?

No para publicar una web ya hecha (Vercel Drop o GitHub). Sí necesitarás entender conceptos básicos para APIs y frameworks.

¿Vercel es gratis?

Existe el plan Hobby, gratuito, para uso personal no comercial y con límites DOC. Otros servicios añadidos pueden costar. Consulta la página oficial de precios.

¿Puedo usar mi propio dominio?

Sí. El dominio se paga al registrador; Vercel solo gestiona la web y el certificado.

¿Qué pasa si publico una clave por error?

Revócala de inmediato en el proveedor, crea una nueva, guárdala como Secret, haz redeploy y revisa el uso de la antigua.

¿Puedo volver a una versión anterior?

Sí, con Instant Rollback. Recuerda promover después un despliegue nuevo para restaurar la publicación automática DOC-PARCIAL.

¿Por qué mi cambio de variable no se nota?

Porque solo afecta a despliegues nuevos: haz redeploy DOC.

¿Puedo publicar una app creada con IA?

Sí, siempre que revises claves y seguridad. No pases a producción código que no entiendas.

¿Vercel gestiona mi correo?

No. El correo de tu dominio lo gestiona otro proveedor; mantén los registros MX.
